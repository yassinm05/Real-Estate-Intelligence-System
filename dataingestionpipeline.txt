Phase 1: Resource InitializationThe pipeline starts by loading your fine-tuned weights and tokenizer from the local ./models/ directory. By using AutoModel instead of AutoModelForSequenceClassification, we strip the classification head and access the "Hidden States"—the raw mathematical representation of your text.Phase 2: The Custom Embedding LogicWe implemented a specialized embedding function to bridge the gap between raw text and ChromaDB.Mean Pooling: Instead of relying on the single [CLS] token, the pipeline calculates the average of all token embeddings (weighted by the attention mask). This captures the full semantic context of a property review.Error Handling: We explicitly disabled token_type_ids and "popped" them from the input dictionary to ensure compatibility with the DistilBERT architecture.Phase 3: Metadata & Payload StructuringThe pipeline prepares three distinct lists to be "zipped" together in the vector database:Documents: The raw comments text.IDs: Unique UUIDs generated to ensure every review is a distinct entry, even if they share a listing_id.Metadatas: A dictionary containing every listing feature (price, latitude, bedrooms, etc.).Note: The pipeline includes a sanitization step that replaces NaN values with empty strings or zeros, as ChromaDB's metadata engine is strictly typed and will reject nulls.Phase 4: Persistent Database ConfigurationThe pipeline initializes the PersistentClient, creating a local physical folder for your data. We configured the collection to use Cosine Similarity:$$ \text{similarity} = \cos(\theta) = \frac{\mathbf{A} \cdot \mathbf{B}}{\|\mathbf{A}\| \|\mathbf{B}\|} $$This is the industry standard for text embeddings because it measures the direction (meaning) of the vector rather than its magnitude (length/word count).Phase 5: The Batch Ingestion LoopTo manage local system memory (RAM/VRAM), the pipeline executes a chunked ingestion strategy:Batching: It slices the 84,000 rows into manageable chunks of 250.In-Flight Embedding: For every batch, the DistilBERT model performs a forward pass to generate vectors.Atomic Commits: ChromaDB writes the IDs, Vectors, and Metadata to the local SQLite/Vector index, ensuring that if the process is interrupted, the data already processed is saved.
